固定账号的 Stack 请求继续跳过熔断器创建及健康记录。参与健康统计的普通请求需要在发出时取得轮次，因此客户端错误路径可能已存在一个零计数熔断器；相关测试检查其仍为 Closed 且计数不变。普通成功结果仍异步记录，半开探测同步记录后再归还名额。

## 无用代码清理

- `useProxyStatus` 中无调用方的 `setTakeoverForAppMutation`、`exitAppsInModeMutation`，及对应返回方法、`isStarting`、`isStoppingServer`、`isInitialStatusPending`。
- `useModeActions.enter` 中空字符串拼接、过期 Desktop 注释和无用的 `restartHint` 依赖。
- `CircuitBreaker::is_available` 无引用别名；删除不带轮次的 `release_half_open_permit`，由私有按轮次释放方法取代。仅测试使用的两个状态迁移方法增加 `cfg(test)`。
- 模式测试内无引用的 `DesktopDirs`、`FakeClients` 及其实现、`stale_clients_of`；代理 handler 测试内无引用的 `authorization_headers`。

## 其他检查

- 入口已有 Origin/Host 检查、依据 TCP 对端的局域网令牌鉴权、入站令牌剥离；未在这些检查路径确认新的凭据泄露缺陷。
- 服务已有入站连接数及请求头读取时间限制；响应体读取和解压有大小上限，SSE 转换有缓冲/状态限制，透传流按消费者拉取数据。
- 原始 HTTP 写入后失败不会退回另一 HTTP 客户端重发同一请求；转发层的故障转移/整流重试仍按现有分类处理。上游已产生结果但连接中断时的计费去重不能仅由本地代理保证。
- 代理自环检查覆盖字面地址、回环别名及匹配端口的域名解析。未进行真实 DNS 故障注入或外部安全渗透测试，不能据此声称已排除所有安全风险。
