# 2026-11-27 启动、闲置与轻量模式验证

本轮基线是用户在 11 月 27 日修改后的工作区快照，没有用 Git HEAD 覆盖用户已有改动。直接启动轻量模式可与本轮修正后的代码作同源对照；原快照的正式前端存在循环依赖并显示空白页，因此不能用它的主界面内存作优化前基线。远端另有一个能正常打开界面的旧二进制，其源码版本不同，只作为历史参考。

## 已确认的问题与修改

- **Windows 轻量模式提前创建 WebView**：`tauri.windows.conf.json` 的窗口数组覆盖公共配置，遗漏了公共配置中的 `create: false`，使 Tauri 在加载轻量模式设置之前自动创建主 WebView。补齐该字段，启动、退出轻量模式时都由现有生命周期代码按需创建。新增公共配置和 Windows 配置的回归检查。这项 Windows 专用修复不影响下表的 Linux 数据。
- 手工 `manualChunks` 把图表依赖与共享辅助代码交叉打包：首页即使没有打开用量页，也会静态加载图表包，还形成 runtime → charts → runtime 循环。实际探针发现原快照根节点为空，模块初始化报 `Cannot access 'C' before initialization`。移除手工分组，让实际动态导入决定分包；托盘的用量页也改为首次打开时加载。修正后真实主界面有 250 个 DOM 节点，正常显示供应商列表。
- 首页启动时预取其他所有可见应用的供应商列表，会额外读取、反序列化并缓存尚未使用的数据。取消这一步，切换应用时按需读取。首次切换需要等待一次本地读取。
- 桌面端与核心后台各自创建 Tokio runtime。桌面端改为复用核心持有的进程生命周期 runtime（两个异步 worker），避免重复线程池。磁盘操作仍使用 blocking 任务。
- 界面已经不再使用心跳样式，窗口活动管理却继续每三秒写一次 DOM 属性。删除心跳、无用焦点快照及对应样式；保留显示、隐藏、最小化的查询暂停/恢复逻辑。
- 删除没有生产入口引用的六个前端模块、仅服务于已移除应用的 Rust 适配器/辅助代码、翻译段落，以及空循环、恒定分支和过时测试。数据库历史兼容列保留；存活应用仍使用的 Gemini 上游协议与 xAI OAuth 逻辑保留。
- 修复原工作区中两个孤立的 Windows 条件编译属性，避免 Linux 编译缺失变量；修复 OpenCode 复制前遗漏的原生 ID 读取，防止生成与现有配置冲突的 ID。

这些修改中，分包和按需读取主要影响启动成本；去掉无用定时器主要影响闲置唤醒；复用 runtime 主要影响后台线程常驻。删除未引用源码主要改善维护性，不能把删除行数直接换算成内存收益。

## 测量条件

- 主机：`10.2.2.24`，Linux；隔离的 Xephyr `:99`、1100 × 750 窗口。
- 两个版本均使用同一 Rust 工具链和同一 release 配置，启用 `tauri/custom-protocol`，内嵌对应的正式 Vite 前端构建。
- 两个版本仅在临时源码副本中加入相同的可选探针，用来读取真实 DOM、已加载资源并执行隐藏/轻量模式切换。探针未写入产品源码。
- 使用独立应用 HOME 覆盖、配置目录、XDG 目录和 D-Bus 会话；不使用真实账号、密钥或会话数据，不替换已安装应用，不停止原有应用进程。客户端更新检查关闭；应用自身前端仍会进行一次更新检查，其 30 秒超时在预热阶段结束。
- 正式对比在编译完成后串行运行。每秒读取整个进程树的 `/proc/*/smaps_rollup` 与 CPU 时间，包含 WebKit 子进程和该隔离会话的 D-Bus 开销。
- CPU 以一个逻辑核心为 100%；PSS 按共享页分摊，更适合评估总物理内存；RSS 求和会重复计入共享页，单独报告。同步记录 SwapPss，避免把换出内存误认为优化。
- 主界面：总计 180 秒，前 90 秒预热；直接启动轻量模式：150 秒，前 90 秒预热。两者各重复两次。隐藏与主界面切入轻量模式：第 90 秒切换，统计第 120–180 秒。
- 页面探针验证实际界面已加载，不将空白页、错误页或启动阶段当成闲置结果。

## 实测数据

以下均为整个隔离进程树的平均值，包含 WebKit 子进程；CPU 以一个逻辑核心为 100%。主界面和直接启动轻量模式取两轮平均，隐藏及切入轻量模式各一轮。

| 场景 | CPU（单核） | PSS（MiB） | RSS（MiB） | 末次线程数 |
| --- | ---: | ---: | ---: | ---: |
| 原快照直接启动轻量模式 | 0.008% | 59.44 | 87.63 | 20 |
| 修正后直接启动轻量模式 | 0.000% | 59.01 | 87.21 | 14 |
| 修正后主界面闲置 | 0.092% | 272.89 | 448.62 | 38 |
| 修正后隐藏主界面 | 0.082% | 269.21 | 444.86 | 38 |
| 修正后从主界面切入轻量模式 | 0.031% | 158.52 | 232.53 | 26 |

所有有效采样的 SwapPss 为 0。直接轻量模式的内存差异仅 0.43 MiB，不能认为已经证明明显降低；线程减少 6 个是稳定的结果。两轮新版主界面 PSS 为 274.34、271.44 MiB，CPU 为 0.088%、0.097%。

历史可用二进制的一轮参考值为主界面 CPU 0.482%、PSS 277.14 MiB、RSS 454.57 MiB；其源码版本和界面语言不同，不能据此报告精确的优化百分比。原快照空白页测量、启动未稳定的采样及编译重叠的探索性数据全部排除。

切入轻量模式会销毁 WebKitWebProcess，但仍保留 WebKitNetworkProcess（末次 PSS 约 22.8 MiB）以及主进程已加载的 GTK/WebKit 资源。锁定版本 `tauri-runtime-wry 2.12.5` 的 `WebviewWrapper::drop` 明确保留 Linux WebContext，以复用无法随 WebView 一起退出的网络进程。这解释了切入轻量模式比冷启动轻量模式高很多，不能将窗口隐藏视为释放 WebView。没有用杀死浏览器子进程或强行换出内存伪造降低。

结论：之前的分包、预取和重复运行时并非都合理；本轮去除了已证实的额外工作，并修复 Windows 轻量启动不生效的配置。Linux 空配置的闲置 CPU 已很低，冷启动轻量模式的内存收益很小；主界面与切入轻量后的 WebKit 常驻仍是主要成本，不能宣称已经解决所有平台的内存上涨。
