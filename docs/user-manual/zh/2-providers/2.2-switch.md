# 2.2 切换供应商

## 连接模式

**Claude Code** 和 **Codex** 的应用页顶部有「直连 / 路由 / 聚合」三个标签：

| 模式 | 请求怎么走                                               | 切换供应商                     |
| ---- | -------------------------------------------------------- | ------------------------------ |
| 直连 | 客户端直接连供应商                                       | 改写客户端配置文件里的关键字段 |
| 路由 | 请求先经过本机的 CC Switch，可格式转换、故障转移         | 只改路由目标，不再改写配置文件 |
| 聚合 | 按 `/model` 里选的模型把请求分给多家供应商，不做故障转移 | 切换的是默认供应商             |

**点标签只是查看那一页，不会改配置。** 真正换模式要点页面上写明后果的按钮：「开始路由」、「切换到聚合模式」、「回到直连」。标签旁的「生效中」标记说明现在实际是哪一种。路由和聚合的详细说明见 [4.2 应用路由](../4-proxy/4.2-routing.md)。

下面先讲最常见的直连切换。

## 主界面切换

在直连页，点击目标供应商卡片上的「切换」按钮。

- **OpenCode** 和 **DeepSeek Harness** 是共存式应用，可以同时添加多个供应商，操作方式见下文 [共存式应用](#共存式应用)。
- **Antigravity** 的官方登录卡直接切换本机模型，第三方 Key 卡通过「打开终端」以隔离目录启动，见下文 [Antigravity](#antigravity)。

### 切换流程

1. 点击「切换」按钮
2. CC Switch 更新配置文件
3. 卡片上的按钮换成「使用中」状态
4. 按各应用的方式生效（见下文「生效方式」）

### 状态指示

| 状态     | 显示                      | 说明                                 |
| -------- | ------------------------- | ------------------------------------ |
| 使用中   | 直连色边框 + 「使用中」   | 直连模式下，配置文件里正在用的供应商 |
| 路由中   | 路由色边框 + 「路由中」   | 路由模式下，实际转发请求的供应商     |
| 当前默认 | 聚合色边框 + 「当前默认」 | 聚合模式下的默认供应商               |
| 普通     | 默认样式                  | 其他供应商                           |

模式和卡片上的按钮对应：

- 在直连页，实际处于路由或聚合时，其他卡片的按钮是「回到直连并使用」。
- 在路由页，其他卡片的按钮是「路由到此」。
- 标有「需要路由」的供应商（比如需要格式转换或托管 OAuth）不能直连，直接切换会弹出提示，可以选择「开始路由并使用它」。
- 官方订阅默认不经过路由（Codex 的 OpenAI Official 例外），在路由页是灰的。

## 托盘快速切换

通过系统托盘可以快速切换，无需打开主界面。

### 操作步骤

1. 打开系统托盘菜单或快捷面板
2. 找到对应应用的子菜单或卡片（支持 **Claude Code** 和 **Codex**）
3. 点击要切换到的供应商名称
4. 切换完成，托盘会短暂提示

### 托盘菜单结构

托盘为 **Claude Code** 和 **Codex** 各建一行子菜单：

| 子菜单      | 说明             |
| ----------- | ---------------- |
| Claude Code | 该应用的供应商   |
| Codex       | 该应用的供应商   |

子菜单标题形如「应用名 · [路由 / 聚合 ·] 在用供应商 · 额度摘要」，不用打开就能看到当前用的是哪家、处于哪种模式。子菜单里的行为跟随当前模式：

- **直连**：点供应商即切换；需要路由的供应商后面标「（需要路由）」，点它会打开应用页并弹出提示。
- **路由**：点供应商即换路由目标；官方订阅标「（官方订阅不经过路由）」，不能点。
- **路由 + 故障转移开启**：只读，列出队列顺序，要调整请到应用页。
- **聚合**：只列聚合名单里的供应商，点一家就是设为默认。

OpenCode、DeepSeek Harness 和 Antigravity 不进托盘切换子菜单，请在主界面操作。

> 💡 **提示**：后台常驻 + 轻量模式 + 托盘切换的组合特别适合频繁切换的用户。参考 [1.5 个性化配置 → 轻量模式](../1-getting-started/1.5-settings.md)。

## 生效方式

### Claude Code

**切换后即时生效**，无需重启。

Claude Code 支持热重载，会自动检测配置文件变更并重新加载。

### Codex

切换后需要重启 Codex：CLI 退出后重新运行 `codex`，桌面版彻底退出（macOS 用 ⌘Q）再打开。

### Antigravity

- **官方登录卡**：切换后写入 `~/.gemini/antigravity-cli/settings.json` 的 `model`，新开的 `agy` 会话立即生效（已运行的进程不热切换）。
- **第三方 Key 卡**：点击卡片上的「打开终端」启动隔离进程（`agy --gemini_dir=~/.cc-switch/agy/<供应商 ID>/`），密钥通过进程环境变量传入。详细原理见 [Antigravity 接入](../../../agy-integration-zh.md)。

### 路由和聚合模式下

请求都经过 CC Switch 转发。在路由页换供应商只改路由目标，对后续请求立即生效；如果换供应商改变了模型目录，Codex 仍需要彻底重启。

路由期间，直连时在用的那家保持不变（卡片上标「直连时使用」），回到直连后配置文件会写回它。

聚合模式下，Claude Code 里聚合模型列表的变化立即生效；Codex 需要彻底重启才能看到新的模型列表：CLI 点页面提示里的「重启 Codex 守护进程」（会中断正在运行的任务），桌面版 ⌘Q 彻底退出再打开，编辑器插件重开窗口。

路由和聚合需要 CC Switch 保持运行。退出 CC Switch 时会自动回到直连，下次启动再接上。详见 [4.2 应用路由](../4-proxy/4.2-routing.md)。

## 配置文件变更

切换供应商时，CC Switch 只替换以下文件里的**关键字段**：请求地址、Key、模型名、接口协议，以及少数跟着供应商走的兼容选项（如上下文窗口）。插件、Hook、权限、MCP、你自己加的设置、注释和排版都原样保留。每个文件具体改哪些键，见 [5.1 配置文件说明](../5-faq/5.1-config-files.md)。

### Claude

```
~/.claude/settings.json
```

修改内容（只示意关键字段，文件里的其他内容不动）：

```json
{
  "env": {
    "ANTHROPIC_API_KEY": "新的 API Key",
    "ANTHROPIC_BASE_URL": "新的端点"
  }
}
```

### Codex

```
~/.codex/config.toml
```

第三方供应商的 API Key 写在 `config.toml` 中 `[model_providers.custom]` 表的 `experimental_bearer_token`，不会写入 `~/.codex/auth.json`。`auth.json` 只用于 OpenAI 官方的 ChatGPT 登录：切换到第三方供应商时，是否保留它由「设置 → 应用配置」里的「非接管切换时保留官方登录」决定。配置了模型映射的供应商还会生成 `~/.codex/cc-switch-model-catalog.json`。

### Antigravity

```
~/.gemini/antigravity-cli/settings.json          # 官方登录模式修改 model 并移除 modelProvider
~/.cc-switch/agy/<供应商 ID>/antigravity-cli/    # 第三方 Key 模式的隔离配置目录
```

## 共存式应用

**OpenCode** 和 **DeepSeek Harness** 支持多个供应商同时写入工具自身的配置，在工具里选择使用哪一个：

| 应用             | 按钮        | 写入位置                                                            |
| ---------------- | ----------- | ------------------------------------------------------------------- |
| OpenCode         | 添加 / 移除 | `~/.config/opencode/opencode.json`                                  |
| DeepSeek Harness | 添加 / 移除 | `$DSH_HOME/profiles/{web,desktop,...}/cordis.patch.yml`             |

添加之后，在工具自身的界面或命令中选择要使用的模型（DeepSeek Harness 也支持在授权中心登录 DeepSeek 账号，Web 与 Desktop 共用 `.credentials.yaml`）。

共存式应用不支持托盘切换和故障转移队列。

## 切换失败处理

如果切换失败，可能的原因：

### 配置文件被锁定

其他程序正在使用配置文件。

**解决方法**：关闭正在运行的 CLI 工具，再尝试切换。

### 权限不足

没有写入配置文件的权限。

**解决方法**：检查配置目录的权限设置。

### 配置格式错误

供应商配置的 JSON / TOML / YAML 格式有误。

**解决方法**：修复对应配置文件或编辑供应商配置后重试。
