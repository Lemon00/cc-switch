# 2026-11-28：10.2.2.24 CPU 与内存实测

本轮基线是模块 05–16 审查完成后的工作区快照，不是 Git HEAD。保留原有未提交修改，只在该快照上修改 5 个会话同步文件和 Linux 入口文件。原始材料位于 `target/perf-20261128/`，包含源码快照、基线/最终 manifest、本轮补丁、采样脚本、逐点数据、构建和回归日志。

## 环境与方法

- Linux Mint 22.3，内核 6.14.0-37-generic，VMware，Xeon E5-2640 v2，6 个逻辑 CPU，MemTotal 12248196 KiB。
- WebKitGTK/JavaScriptCore 2.52.6，Rust 1.95，锁定依赖、离线 release 构建，`tauri/custom-protocol`。三版使用相同正式前端 dist、Cargo.lock 和编译优化设置。构建并发不同，但不改变代码生成选项。
- Xephyr X11 `:99`，1100×750。每次使用全新的 `CC_SWITCH_TEST_HOME`、配置、XDG、DSH 与 D-Bus 会话，不复制真实账号、密钥或历史会话。
- 基线、同步优化版、最终版的远端源码副本均带相同临时回环地址探针，用于真实 WebView IPC 和窗口切换。仓库产品源码不含探针，测试构建不用于安装分发。
- 对应用整个子进程树读取 `/proc/stat`、`smaps_rollup`；包括 WebKit 和隔离 D-Bus，不包括 Xephyr、Python 采样器。CPU 以单个逻辑核为 100%。PSS 分摊共享页，RSS 求和会重复计算共享页，内存单位为 MiB。
- 普通场景运行 155 秒，统计第 90 秒之后；隐藏/切入轻量在第 90 秒执行，统计第 120–180 秒；冷轻量恢复窗口在第 90 秒执行，统计第 150–210 秒。
- 合成负载在第 50 秒开始，每次同步前后 0.25 秒采样，其他场景约 1 秒采样。峰值可能漏掉更短的瞬时分配。

## 修改与原因

1. `session_usage.rs`、`session_usage_agy.rs`、`session_usage_dsh.rs`、`session_usage_opencode.rs`：按本轮实际文件或会话的精确键，使用参数化查询每批最多读取 512 个游标，避免重复复制其他客户端和已移走文件的历史解析状态。空列表不访问数据库；选中行读取失败仍中止同步，避免把错误当成新文件而重复导入历史用量。
2. `session_usage_codex.rs`：删除重复的字节偏移映射，在同一个游标快照保存修改时间、行偏移和字节偏移。只保留当前文件及同名 rollout 的历史归档/压缩路径，继续支持跨目录游标继承。这里仍需扫描游标表以发现历史别名，不能宣称全部改成了索引查找。没有删除数据库里的历史游标。
3. `src-tauri/src/main.rs`：Linux 在 GTK 初始化之前默认设置 `GDK_GL=disable`，保留用户显式设置。程序已有 WebKit 软件渲染策略；本改动避免纯托盘启动时额外初始化 GTK GL。独立环境变量实验中，冷轻量 PSS 从 111.0 降到 61.2 MiB；内存映射显示此前单独加载的 LLVM 占约 42.5 MiB，关闭后不再出现在冷轻量的映射中。

## 冷轻量与切入轻量为什么不同

`src-tauri/src/lib.rs` 的启动逻辑在轻量模式下跳过主窗口创建；`src-tauri/src/lightweight.rs` 的运行中切换会销毁已创建的窗口，并释放会话缓存、收缩 SQLite 内存、调用进程堆整理。因此两条路径有不同的初始化历史。

实际使用的 `tauri-runtime-wry 2.12.5` 在 `WebviewWrapper::drop` 中明确为 Linux 保留 WebContext，目的是复用 WebKit 不会随最后一个窗口自动关闭的网络进程。对应依赖源码片段保存在 `measurements/tauri-webcontext-lifetime.txt`。

同步优化版实测：冷轻量 111.0 MiB、主界面切入轻量 158.6 MiB。末次采样中，后者多出约 23.9 MiB 的 WebKit 网络进程；主进程由约 110.1 增至 133.7 MiB，主要是更多已访问的 WebKit/JavaScriptCore、应用代码页及少量堆资源。页面渲染进程确已退出。普通隐藏窗口仍约 277.4 MiB，几乎不释放界面资源。

这些驻留资源不能仅凭一次采样称为泄漏。当前没有验证多轮切换是否持续增长。要让打开过界面的进程回到从未初始化 WebView 的水平，通常需要重建进程或拆分 UI 生命周期；这会涉及代理连接、托盘和状态交接，本轮没有据此自动重启用户进程。

## 适用范围

这是 Linux X11 隔离环境下的空闲与合成同步测量，不代表 Windows WebView2、Wayland/NVIDIA、真实账号刷新、长对话解析或并发代理负载。测试中有外部模型目录 DNS 失败及更新检查超时，统计窗口在预热之后；同步业务结果没有错误。主界面空闲 CPU 为低于 1% 的小数值，不能据此声称同步优化降低了所有常驻 CPU 或主界面内存。

## 切入轻量的进一步检查

进一步只读核对与远端匹配的 WebKitGTK 2.52.6 官方源码，参考文件保存在 `target/perf-20261128/webkit-reference/`。`WebProcessPoolGLib.cpp` 初始化页面进程时仍调用 `drmMainDevice()`；`DRMMainDevice.cpp` 默认经 `Display::glDisplay()` 查询 EGL 设备。这条路径解释了为什么关闭 GTK GL、WebGL 和合成之后，创建过页面的主进程仍会加载 Mesa/LLVM。远端 `readelf` 也确认 `libgallium` 直接依赖 LLVM。

WebKit 的 `webkit_web_context_clear_cache` 清除的是网站内存/磁盘缓存，不会卸载图形库；本仓库已使用 DocumentViewer、禁用页面缓存，并在切入轻量时回收会话缓存、SQLite 和 glibc 空闲堆页。剩余映射和 WebKit 网络进程不能等同于业务缓存。没有采用强杀网络进程、手动卸载共享库、伪造 GPU 路径或重启代理来压低数字；本轮进一步检查没有新增经实测证明有效的产品代码修改。

另做同进程回收实验 `retrim-final`：使用原最终二进制和既有临时探针，第 90 秒切入轻量，第 155.87 秒再次执行已有的轻量清理（会话缓存、SQLite、glibc 堆整理）。第 120–150 秒 PSS/RSS 均值为 140.662 / 229.873 MiB，第 185–235 秒为 140.645 / 229.855 MiB，仅减少 **0.0175 MiB，约 18 KiB**，不足以支持增加重复回收代码。此诊断使用旧采样脚本，不混入上面的官方成品对照表，结果及触发时间单独保存在 `retrim-analysis.json`、`retrim-final.retrim.json`。

还检查了显式指定真实 DRM 设备以绕过自动 EGL 探测的可能性：远端只有 VMware `vmwgfx` 对应的 `/dev/dri/renderD128`，当前用户无读写权限，因此该实验跳过，没有使用无效设备路径，也没有改变设备权限。该思路尚无本机有效实测结果，不能作为已完成优化。

本轮结束时停止专用 Xephyr `:99`，确认无残留测试应用，也没有需要额外终止的测试 profile 桌面辅助进程；SSH、Xorg/XRDP 与用户桌面保留。关闭记录见 `cleanup-final.json`。原始数据、官方包、来源校验、视觉审核和汇总均保存在 `target/perf-20261128/`；源码 6 文件再次核对 `final-manifest.json` 一致，未提交或暂存原有工作区改动。
